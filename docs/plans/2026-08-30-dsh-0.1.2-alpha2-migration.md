# @huanlin/dsh-plugin-mcp-manager · dsh 0.1.2-alpha.1 → alpha.2 迁移指南

## 迁移步骤

> 顺序：**先**把 dsh 源码 checkout 升到 alpha2（DSH 源码 SOP：`git pull --ff-only` → `pnpm install --prefer-offline` → `pnpm run build`，由人类执行，本插件仓库不含该步骤），**再**做下面各步。

### 1. 源码：无需改动

逐项对照「影响对照表」#1–#20：`src/`、`cordis.patch.yml`、`tsdown.config.ts`、`tsconfig.json` 均无需任何修改。无新增 import、无改名适配、无事件/类型迁移。

### 2.（可选，卫生操作）peer 范围对齐 alpha2

`package.json` 中 8 个 `@deepseek-ai/*` peer 从 `^0.1.2-alpha.1` 对齐为 `^0.1.2-alpha.2`：

- **非必须**：semver 上 alpha1 范围已满足 alpha2（对照表 #17 实证）。
- 对齐的收益：语义上声明「已按 alpha2 验证」；并规避未来 `0.1.3-alpha.x` 到来时的 tuple 失配遗忘。
- 若做：bump 版本 `0.2.0 → 0.2.1`，随后提交 `package.json`。`lib/` 产物不受影响（`tsdown.config.ts:21,34` 将 `@deepseek-ai/*` 全部 external，peer 范围不进产物），但**预构建策略下 package.json 变更需要随 lib/ 一起提交**。
- 不改 `@deepseek-ai/cordis ^4.0.1`（4.0.2 本就落在范围内，收窄无收益）。

## 升级后验证清单

> 前置：dsh 源码已升到 alpha2 且完成 install + build；`dsh web` 已重启；浏览器已 `Ctrl+Shift+R` 硬刷新。

1. **面板挂载**：设置页出现「MCP」分区（order 61，位于既有分区之后），标题「MCP 服务器」/「MCP Servers」随语言切换。
2. **存量读取（向后兼容）**：面板列出 alpha1 时代写入的全部服务器行；此前禁用过的行显示「已禁用」灰化（entry-level `disabled` 仍被 loader 与本插件识别——对照表 #12）。
3. **新增 → HMR 挂载**：新增一台 stdio 测试服务器（如 `npx` + 轻量 MCP server）→ 状态走「连接中…」（≤30s 宽限窗，面板 2s 自动轮询）→ 变为「N 工具」；点「工具」展开可见 `mcp__<serverName>__*` 列表。这同时验证了配置 HMR 在 alpha2 仍实时挂载 mcp-client。
4. **禁用/启用**：点「禁用」→ 状态「已禁用」、卡片半透明、工具列表不可展开；agent 侧 `mcp_server_list` 该行 `disabled: true`；再「启用」→ 恢复「连接中→已连接」。
5. **agent 五工具冒烟**：依次调用 `mcp_server_list` → `mcp_server_add` → `mcp_server_update`（改 timeout）→ `mcp_server_set_enabled` → `mcp_server_remove`，确认每步返回 `ok: true` 且面板同步。
6. **删除**：DELETE 后 patch 行移除、工具注销；若该 insert 块被清空，确认文件中空 `- insert:` 条目一并清除（防脏 patch）。
7. **写回保真**：手工在 profile `cordis.patch.yml` 其他行加注释或 `!!js` 表达式，再经面板增删改一次，确认注释与 `!!js` 原样保留（eemeli Document 往返，对照表 #11）。
8. **失败路径**：对已连接服务器执行一次会被 `loadOverlayPatches` 拒绝的构造（或临时令 patch 非法）→ 面板报「写入后校验失败（已回滚）」且文件内容复原。
9. **（可选，若装有 better-locale）**：切换 override 语言，确认 19 语言字典生效（`ctx.get('betterLocale')` 通路，对照表 #6 之 locale subscribe 面未变）。
