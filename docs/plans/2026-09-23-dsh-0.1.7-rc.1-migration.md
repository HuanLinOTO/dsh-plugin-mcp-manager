## 插件形态

- **Host 半**：`/api/mcp-manager` 路由（经 `ctx.webServer`）+ `mcp_*` agent 工具（`ctx.tools`）+ 读写 profile `cordis.patch.yml` 的 `@deepseek-ai/dsh-mcp-client` insert 行（配置 HMR 挂载）。
- **Client 半**：注册 `settings.section` 的「MCP」面板（`src/client`，tsconfig 排除，不参与 typecheck）。
- 连接生命周期委托官方 `@deepseek-ai/dsh-mcp-client`（optional peer `@deepseek-ai/dsh-app-boot` 仅用于写后校验 `loadOverlayPatches`）。

## RC1-15 / mcp-client insert 行合法性确认

- 本插件 manifest：`"dsh": { "bundle": { "patch": "./cordis.patch.yml" } }`——RC1-15 后 `patch` 为 `string | string[]`，**字符串仍合法**；未被删除的 `dsh.profile.patchReload`/`configTrees`/`sessionFormatMigration`/`moduleFallback` 均不存在；`dsh.manifestVersion` 为新增可选元数据，非必填。
- 插件写入的是 **profile 的 `cordis.patch.yml` insert 行**（组合层），不是 bundle 的 `package.json.dsh` manifest。RC1-15 改的是 bundle manifest 契约，组合 insert 行语义未变。
- 写后校验走 `@deepseek-ai/dsh-app-boot` 的 `loadOverlayPatches(binName, file)`：rc.1 `dsh-app-boot` **仍导出** `loadOverlayPatches`（见 `lib/types/index.d.ts:98`，`bundlePatchPaths` 也在 `profile.d.ts:52`）——校验路径完整。
- `@deepseek-ai/dsh-mcp-client` 包名未改；insert 行 `name` 仍是 `@deepseek-ai/dsh-mcp-client`。
